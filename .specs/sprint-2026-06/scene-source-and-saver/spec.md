# SPEC-2026-001 — Scene Source Tracking and Saver

## Problem

When the `SceneLoader` processes an entity with a `prefab:` or `model:` directive, it expands the reference into a full entity tree (loading components, children, etc.). However, the resulting entities have no memory of their origin — after loading, there is no way to tell that an entity was created from a prefab or from a model file. This makes it impossible to serialize the `World` back to YAML without losing the original `prefab:` and `model:` references: the saver would write the entire expanded entity tree instead of compact reference directives.

Without source tracking:
- Saving a prefab-based scene would produce a flat, uneditable dump of all prefab-internal entities.
- Saving a model-based scene would produce a huge tree of mesh-node entities instead of a clean `model:` reference.
- Scene files generated by the saver cannot be re-loaded as the original concise form.

## Goals

- **G-01**: Add an `EntitySource` struct and `EntitySourceType` enum to track whether an entity was created directly, from a prefab, or from a model directive.
- **G-02**: Store `EntitySource` on each `World::EntityNode`, with accessors `Entity::source()` and `Entity::set_source()`.
- **G-03**: `SceneLoader::load_entity()` sets the source when creating entities from `prefab:` (`EntitySourceType::Prefab`) or `model:` (`EntitySourceType::Model`). Model child entities created by `add_model_to_world()` get source `EntitySourceType::None`.
- **G-04**: Create a `SceneSaver` class in `src/engine/scene/scene_saver.h/.cpp` symmetric to `SceneLoader`, with API: `save_to_file(path) -> Result<void>` and `save_to_yaml() -> YAML::Node`.
- **G-05**: `SceneSaver` serializes entities back to YAML respecting source type:
  - `Prefab` source → emit only `prefab:` + `name:` + `transform:` (components/children are part of the prefab definition).
  - `Model` source → emit only `name:` + `model:` + `transform:` (mesh children come from the model file).
  - `None` source → emit full entity: `name:`, `transform:`, `components:`, `children:` recursively.
- **G-06**: Provide at least 6 unit tests covering source tracking and scene saving (including round-trip).

## Non-goals

| # | Exclusion |
|---|---|
| NG-01 | No editor integration — engine-only change. |
| NG-02 | No saving of entity `type:` or `version:` metadata from World (SceneSaver always writes `type: Scene` and `version: 1`). |
| NG-03 | No partial component overrides on prefab or model entities — they are immutable outside of transform. |
| NG-04 | No YAML schema validation beyond what yaml-cpp provides. |
| NG-05 | No recursive scene file saving (e.g., saving prefabs to their original files). The saver writes a single scene YAML file. |
| NG-06 | No changes to `add_model_to_world()` — model child entities simply get source `None` and the parent entity's `Model` source prevents them from being serialized. |
| NG-07 | No runtime scene hot-reload or file watching. |
| NG-08 | No changes to `SceneLoader`'s error handling or transform composition logic. |

## Key entities

### `EntitySourceType` enum

```cpp
namespace buddd::engine {

enum class EntitySourceType : uint8_t {
    None,    // Created directly (no prefab/model) — default
    Prefab,  // Created from a prefab file via `prefab:`
    Model,   // Created from a model directive via `model:`
};

} // namespace buddd::engine
```

### `EntitySource` struct

```cpp
namespace buddd::engine {

struct EntitySource {
    EntitySourceType type{EntitySourceType::None};
    std::string path;  // Path to the prefab or model file (empty for None type)
};

} // namespace buddd::engine
```

### `World::EntityNode` addition

```cpp
struct EntityNode {
    EntityId id_;
    Transform transform_;
    std::string name_;
    EntitySource source_;                // NEW
    EntityNode* parent_ = nullptr;
    std::vector<std::unique_ptr<EntityNode>> children_;
    std::vector<std::unique_ptr<Component>> components_;
    World* world_ = nullptr;
    bool pending_destroy_ = false;
};
```

### `Entity` class additions

```cpp
// In entity.h:
auto source() const noexcept -> const EntitySource&;
void set_source(const EntitySource& source);
```

### `SceneSaver` class (`src/engine/scene/scene_saver.h/.cpp`)

```cpp
namespace buddd::engine {

class SceneSaver {
public:
    SceneSaver(World& world, ComponentRegistry& registry, AssetManager& assets);

    /// Save the World to a YAML file.
    [[nodiscard]] auto save_to_file(const std::string& path) -> Result<void>;

    /// Save the World to a YAML::Node (useful for testing and in-memory workflows).
    [[nodiscard]] auto save_to_yaml() -> YAML::Node;

private:
    /// Serialize a single entity to a YAML node.
    auto save_entity(Entity entity) -> YAML::Node;

    World& world_;
    ComponentRegistry& registry_;
    AssetManager& assets_;
};

} // namespace buddd::engine
```

### YAML output structure

**Basic scene** (all source type `None`):
```yaml
type: Scene
version: 1
entities:
  - name: my_entity
    transform:
      position: [1.0, 0.0, 0.0]
    components:
      - type: camera
        properties:
          fov_y: 1.047
    children:
      - name: child_entity
        transform:
          position: [1.0, 0.0, 0.0]
```

Note: Transform fields at default values (position=`[0,0,0]`, rotation=`[1,0,0,0]`, scale=`[1,1,1]`) are omitted. Component properties at their registered default values are also omitted. Only non-default values appear in the output.

**Prefab entity** (source type `Prefab`):
```yaml
  - prefab: prefabs/free_camera
    name: main_camera
    transform:
      position: [3.0, 2.0, 3.0]
```

**Model entity** (source type `Model`):
```yaml
  - name: my_box
    model: models/box/Box
```

Note: If all transform fields are at defaults, the entire `transform:` block is omitted.

## Actors

| Actor | Description |
|---|---|
| **Developer** | Uses `SceneSaver` to programmatically save a `World` to a YAML scene file. |
| **Editor developer** | Uses `EntitySource` to determine which entities can be edited (only `None` source entities have mutable components/children). |
| **Content creator** | Benefits from saved scene files that preserve `prefab:` and `model:` references instead of expanded entity trees. |
| **Test runner** | Runs unit tests that verify source tracking and save/load round-trip. |

## User-visible behavior

This feature is primarily engine-internal — there is no direct user-facing command or UI. However, the following behaviors become observable through the `SceneSaver`:

- Calling `SceneSaver::save_to_yaml()` produces a YAML node whose structure mirrors the input YAML accepted by `SceneLoader`, with `prefab:` and `model:` references preserved.
- Entities created directly (`World::add_entity()`) have `source().type == EntitySourceType::None`.
- Entities loaded from `prefab:` have `source().type == EntitySourceType::Prefab` and `source().path` set to the resolved prefab path.
- Entities loaded from `model:` have `source().type == EntitySourceType::Model` and `source().path` set to the model asset ID string.
- Child entities created by `add_model_to_world()` (model mesh expansion) have `source().type == EntitySourceType::None`. They are not saved separately because their parent's `Model` source causes the saver to emit only a `model:` reference.
- Saving a `World` that was loaded from YAML and then re-saved produces YAML that, when loaded again, yields the same entity tree (round-trip fidelity), within the constraints of floating-point precision and entity ordering.

## User stories

### Story 1 — Entity source tracking after loading (Priority: P1)

As a developer, I want entities to remember whether they came from a prefab or model, so I can inspect their origin at runtime.

**Given** a World with a SceneLoader
**When** I load an entity with `prefab: prefabs/free_camera`
**Then** the resulting entity has `source().type == EntitySourceType::Prefab` and `source().path` is non-empty

**Given** a World with a SceneLoader
**When** I load an entity with `model: models/box/Box`
**Then** the resulting entity has `source().type == EntitySourceType::Model` and `source().path == "models/box/Box"`

**Given** a World with a SceneLoader
**When** I load an entity with a `model:` directive
**Then** each child entity created by `add_model_to_world()` has `source().type == EntitySourceType::None`

### Story 2 — Save a simple scene (Priority: P1)

As a developer, I want to save a World containing directly-created entities to a YAML file, so I can persist the scene.

**Given** a World with one entity that has a name and transform
**When** I call `SceneSaver::save_to_yaml()`
**Then** the returned YAML node has `type: Scene` and `version: 1` and an `entities:` array with one entry
**And** the entity entry contains `name:`, `transform:`, and optionally `components:` and `children:`

### Story 3 — Save a prefab entity as prefab reference (Priority: P1)

As a developer, I want the scene saver to emit `prefab:` instead of expanding prefab internals, so that saved files remain compact and editable.

**Given** a World containing an entity with `source().type == EntitySourceType::Prefab` and `source().path == "prefabs/free_camera"`
**When** I call `SceneSaver::save_to_yaml()`
**Then** the YAML for that entity contains `prefab: prefabs/free_camera` and does NOT contain the expanded component list or children from the prefab

### Story 4 — Save a model entity as model reference (Priority: P1)

As a developer, I want the scene saver to emit `model:` instead of expanding model mesh children, so that saved files remain compact and editable.

**Given** a World containing an entity with `source().type == EntitySourceType::Model` and `source().path == "models/box/Box"`
**When** I call `SceneSaver::save_to_yaml()`
**Then** the YAML for that entity contains `model: models/box/Box` and does NOT contain the expanded mesh child entities

### Story 5 — Save entity with custom components (Priority: P2)

As a developer, I want components on directly-created entities to be serialized into the saved YAML, so that component data is preserved.

**Given** a World with an entity that has source type `None` and a CameraComponent with `fov_y: 1.0`
**When** I call `SceneSaver::save_to_yaml()`
**Then** the entity's YAML includes a `components:` array with a `camera` entry whose `properties` contain `fov_y: 1.0`

### Story 6 — Round-trip save then load (Priority: P2)

As a developer, I want to save a scene and then load it back, verifying that entity properties are preserved.

**Given** a World with entities of various source types
**When** I save the World to YAML via `SceneSaver::save_to_yaml()`
**And** load the saved YAML into a fresh World via `SceneLoader::load_from_yaml()`
**Then** the new World has the same entity count, names, transforms, and source types as the original

## Edge cases

| Case | Expected behavior |
|---|---|
| Entity with source type `None` but empty name | Saved with `name:` set to empty string (or omitted — consistent with SceneLoader behavior). |
| Entity with source type `None` and no components | `components:` key is omitted entirely (resolved in Q01). |
| Entity with source type `Prefab` and a transform override | Saved with `prefab:` path, `name:`, and `transform:` containing only the override values. |
| Entity with source type `Model` and no explicit transform | Saved with `model:` path and `name:`. `transform:` block is omitted entirely if all fields are at defaults. |
| Entity with all-default transform | `transform:` key omitted entirely from saved entity YAML (no position/rotation/scale). |
| Entity with partial transform defaults | Only non-default fields emitted (e.g., only `position:` if rotation and scale are default). |
| Component with all-default properties | `properties:` key omitted from the component entry in saved YAML (e.g., `{type: camera}` with no `properties:`). |
| Entity with source type `None` and deeply nested children | Full recursive save of all children, each with their own source type. |
| World with zero entities | Saved YAML has `type: Scene`, `version: 1`, `entities: []` (empty sequence). |
| Entity with source type `None` whose child has source type `Prefab` | Parent saved with full expansion, child saved as prefab reference. |
| Round-trip floating-point precision | Transform values saved as YAML floats; on re-load, values should match within `1e-5f` tolerance. |
| Entity source path containing special YAML characters | Path is serialized as a YAML string, properly escaped by yaml-cpp. |
| Entities marked for destruction (pending_destroy_) but not yet flushed | Skipped — not included in saved output. The caller should ensure `World::flush_destroyed()` is called before saving if this behavior is undesired. |
| Component type has no corresponding `ComponentInfoBase*` (unregistered) | `save_entity()` fails — error is propagated; entire save fails. |

## Error cases

| Case | Expected behavior |
|---|---|
| File write failure (e.g., permissions, disk full) | `save_to_file()` returns error with `Error::Category::IoFailed` and descriptive message. |
| YAML node creation fails due to memory (unlikely) | `save_to_yaml()` may return an error or throw; yaml-cpp throws on allocation failure — caught and wrapped in `Result`. |
| Component serialization failure (e.g., unregistered component) | Error is propagated; entire save fails. |

## Permissions and security

- The scene saver writes files only to the filesystem (no network access).
- All file paths are provided by the caller — no external input injection.
- Existing files at the target path will be overwritten (caller responsibility).
- No elevated privileges are required.
- No secrets or credentials are consumed.

## Observability

| Signal | Source |
|---|---|
| Scene save started | `BUDDD_LOG_INFO("Saving scene: {}", path)` in `SceneSaver::save_to_file()`. |
| Scene save complete | `BUDDD_LOG_INFO("Scene saved: {} entities", count)` after save. |
| Component serialization failure | `BUDDD_LOG_ERROR("Failed to serialize component '{}': {}", type, message)` then error is propagated; save fails. |

## Out of scope

- Editor integration (save button, file dialogs, scene hierarchy panel).
- Saving prefab files — only scene files are written; prefabs remain hand-authored V1 assets.
- Partial prefab component overrides (editor/gameplay-only concern outside this spec).
- YAML difference/merge utilities.
- Binary or non-YAML scene serialization formats.
- Saving to non-file destinations (network streams, clipboard, stdout).
- Schema validation on the saved YAML output.
- Recursive scene file saving (a scene cannot contain a reference to another scene file via `scene:` directive — not a YAML scene file concept).

## Assumptions

| ID | Assumption |
|---|---|
| A-01 | `yaml-cpp` is already available as a dependency (used by existing `SceneLoader` and component registry). |
| A-02 | `serialize_component()` from `component_registry/serialization.h` correctly serializes all registered component types to YAML nodes. |
| A-03 | `SerializationContext` required by `serialize_component()` is constructible from `AssetManager&` (same as loader's deserialization). |
| A-04 | Entity ordering in the saved YAML follows the iteration order of root entities and children in the `World` storage (deterministic but not guaranteed stable across World modifications). |
| A-05 | The `World` entity iteration order is depth-first root entities then their children — consistent across calls unless entities are added/destroyed. |
| A-06 | `EntitySource` is trivially copyable enough for storage in `EntityNode` (a small struct with `uint8_t` enum + `std::string` — not trivially copyable due to `std::string`, but movable). |
| A-07 | The `EntitySourceType` enum fits in a `uint8_t` with room for future additions. |
| A-08 | Model child entities created by `add_model_to_world()` are correctly identifiable as having source type `None` even though their parent has source type `Model`. |
| A-09 | The `tests/CMakeLists.txt` glob pattern `tests/*_tests.cpp` will auto-discover `scene_saver_tests.cpp` — no CMake change needed. |
| A-10 | Scene files saved by `SceneSaver` that reference prefabs assume the prefab files exist at the same relative paths when later loaded by `SceneLoader`. |

## Risks

| ID | Risk | Mitigation |
|---|---|---|
| R-01 | **Stale prefab references**: If a prefab file is renamed or deleted after a scene is saved with `prefab:` references, the saved scene file will fail to load. | Documented assumption A-10. Future editor versions may include path validation or a prefab asset database. |
| R-02 | **Component serialization failure**: If a component type registered in `ComponentRegistry` does not have a corresponding `serialize_component()` implementation that works correctly, the saved YAML may be missing component data. | The `serialize_component()` function is already tested by existing code. Adding a unit test for each registered component type is the responsibility of the component owner. |
| R-03 | **YAML output size**: Saving a World with thousands of entities produces a large YAML file. Acceptable for V1 (YAML is human-readable, not optimized for size). | No mitigation needed for V1. Future versions may support binary serialization. |
| R-04 | **Entity iteration order non-determinism**: If `World` entity iteration order is not stable, the saved YAML may differ between saves even without semantic changes. | Documented in assumption A-04/A-05. If determinism is required, a stable-iteration mechanism should be added to `World`. |
| R-05 | **ComponentInfoBase reverse lookup**: `SceneSaver` needs to map a stored `Component*` to its `ComponentInfoBase*` for serialization. The `ComponentRegistry` supports `describe(name)` (string → info) and `create(name)` (string → component), but there is no built-in `component_type_name()` virtual method on `Component` or registry method to reverse-lookup info from a component pointer. | The implementation must add a mechanism (e.g., iterate `EntityNode::components_`, for each component try each registered type via `dynamic_cast` + `registry.describe()`, or add a `const char* type_name() const` virtual on `Component`). This is an implementation detail that the contract must address. |
